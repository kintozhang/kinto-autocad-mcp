# 批量中断后的检查与恢复

适用于 execute_trebi_batch。当前没有自动续跑、自动回滚或自动清除互斥标记功能。

## 先看回执，避免重放

- submitted=false / preflight_rejected 或 target_rejected：绘图工具未提交写入；纠正输入或恢复目标文档后再规划。
- submitted=true / partial_or_unknown：可能已有修改。记录 receipt 指向的 report.json 和执行诊断中的 operation_id。
- 步骤 completed：该次工具调用及其检查已完成，不代表全部工程或保存重开验收完成。
- failed：工具明确返回失败，result 可能包含 created_handle 或 created_wire_handles；这些对象可能已存在。
- failed_or_unknown：捕获了异常，已保存 failed_step/error；不代表该步骤完全没执行。
- entered：进程终止或回执未完成，结果未知，不能由缺少返回句柄推断未创建对象。

## 核对实际图纸

先用 get_execution_diagnostics 读取互斥状态与执行记录；若互斥保护拦住普通工具，不绕过它运行新的写操作。按现有受控维护流程只读检查实际实例、活动文档、命令状态及原始回执。

逐项核对 report.json 中 entities、wires 和最后失败步骤 result 保存的句柄：元件属性、原生接线点、导线两端、图层和线号。没有句柄时，按本次目标图页与执行前清单比对新增对象；不能只按外观或当前对象总数认定结果。

保持失败现场和日志，不自动保存覆盖用户改动、不批量删除对象、不重新运行整份配方。需保留现场时，在核对文档后另存独立检查副本；恢复取舍须基于实际对象证据。

## 处理方式

对于可重建的独立 POC，优先保留失败工程，重新准备另一个空白测试工程再运行。对于需要保留的部分结果，应先形成逐对象修复清单，再执行已确认的局部操作，并重新验收线网、保存重开和报表。现有批量入口会拒绝已有内容的图纸，不承担局部续跑。

只有证明没有仍在执行的工作进程、实际 CAD 状态与失败记录相符之后，才可按受控维护流程处理阻断标记；删锁文件不是修复方法。本文不授予无条件解除保护的权限。

## 已验证范围

这是故障注入测试，不是实际杀死 AutoCAD/工作进程的恢复验收。实际已有图拒绝、错误目标拒绝、正式用途拒绝及图纸不变验证另见 delta-batch-validation.md。
