# 三线传感器路径预检（v5）

2026-09-27：默认 `plan_trebi_batch` 新增 `schema_version=5`、`recipe=remote_io_sensor_paths`、`purpose=test_only`。
这是只读路径预检，不是已完成的绘图配方。`execute_trebi_batch` 返回 `qualification_required`，不提交批次写入。v1–v4执行规则保留。

输入必须包含 manifest、mapping、routes、sensor。manifest限定有效逻辑页102、300；mapping沿用v2的ESI哈希与版本、原始信号/端子、目标端口/通道、PLC地址和来源分栏。sensor指定VPX11IN3、显式PNP测试假设，实物型号与输出类型可为null。

三条路径完整登记：供电针1、0V针3、信号针4；参考连接器针4/5/7、电缆芯1/2/4。检查针脚错配、供电互换、重复芯线/端子、器件身份冲突、安全用途误入和信号/线号混用。插头与插座只声明配对，不伪造跨两半的导线。

R2端点从既有厂家端子清单解析，例如Port0/通道1对应TB2:X01、Electrical接点X4TERM02；测试S/S接TEST_0V。R2通道不是NC50全局地址。输入类型是测试假设，预检不会证明实际传感器兼容性或实物接线。

本轮真实默认stdio会话预检通过；新增20项回归，总计591项通过、3项integration未运行。内部执行函数拒绝v5的测试确认未调用CAD连接；MCP通用写工具的目标/实例守卫仍可能先做只读检查，不能将其描述为整个服务完全不访问CAD。
